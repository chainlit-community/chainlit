This guide is for apps running `chainlit` 2.12.0. If you are on an older version, first read the [2.12.0 section of the changelog](../../CHANGELOG.md#2120---2026-08-25): it changed the MCP configuration and the `@chainlit/react-client` connection API in breaking ways, for the reasons given in the [MCP security advisory](../security-advisory-2026-mcp.md).

## Who should upgrade, and why

Everyone who runs Chainlit.

- The original repository, `Chainlit/chainlit`, has been archived by its owners. Maintenance continues in [chainlit-community/chainlit](https://github.com/chainlit-community/chainlit), which fixes security issues and bugs and removes functionality, but does not add features.
- The `chainlit` distribution on PyPI belongs to the original project. It does not receive the fixes made here.
- 3.0.0 contains security fixes that are not in 2.12.0:
  - A client could choose a Socket.IO session id that made the server write uploaded files into, or recursively delete, a directory outside the session files directory, or share another session's files directory. Session ids are now validated. See [Session ids are validated](#session-ids-are-validated).
  - The minimum versions of `fastapi`, `starlette`, `python-socketio`, `mcp`, `python-dotenv`, `python-multipart` and `pyjwt` are raised to releases without known advisories. See [Minimum dependency versions are raised](#minimum-dependency-versions-are-raised).
  - The OAuth state cookie is compared in constant time, and a missing state cookie is rejected.

## Before you upgrade

### Check your Python version

3.0.0 requires Python `>=3.11.5,<3.14.0`. Python 3.10 and Python 3.11.0 to 3.11.4 are no longer supported; see [Python 3.10 and early 3.11 are no longer supported](#python-310-and-early-311-are-no-longer-supported).

```sh
python --version
```

### Switch to the `chainlit-community` distribution

The distribution is renamed from `chainlit` to `chainlit-community`. Your code does not change: the import package is still `chainlit` and the command is still `chainlit`.

Uninstall `chainlit` **before** installing `chainlit-community`. Both distributions provide the same `chainlit` import package, so when both are installed they overwrite each other's files.

Use the block that matches your tooling:

```sh
# pip
pip uninstall chainlit
pip install chainlit-community==3.0.0
```

```sh
# uv, in a project
uv remove chainlit
uv add chainlit-community==3.0.0
```

```sh
# uv, without a project
uv pip uninstall chainlit
uv pip install chainlit-community==3.0.0
```

```sh
# poetry
poetry remove chainlit
poetry add chainlit-community==3.0.0
```

Then:

- In `requirements.txt`, `pyproject.toml` and constraint files, replace `chainlit` by `chainlit-community`. Extras move with the name: `chainlit[custom-data]` becomes `chainlit-community[custom-data]`.
- If you installed `chainlit-community` while `chainlit` was still present, or uninstalled `chainlit` afterwards, the `chainlit` package on disk may be incomplete. Uninstall both and install `chainlit-community` again.
- Check that nothing brings the original back. A third-party package that depends on `chainlit` makes the installer add it alongside `chainlit-community`:

  ```sh
  pip show chainlit
  ```

  This should report that the package is not found. If it is installed, the `Required-by` line names what depends on it.

- If you download release files by name, they are now `chainlit_community-<version>-py3-none-any.whl` and `chainlit_community-<version>.tar.gz`.

## Breaking changes

### The distribution is renamed to `chainlit-community`

- **What changed:** the project is published on PyPI as `chainlit-community` instead of `chainlit`. The import package (`chainlit`), the command (`chainlit`) and the extras (`custom-data`, `tests`, `mypy`) keep their names.
- **Who is affected:** everyone who installs Chainlit, and every package that declares a dependency on `chainlit`.
- **What to do:** follow [Switch to the `chainlit-community` distribution](#switch-to-the-chainlit-community-distribution). If you publish a package that depends on Chainlit, change its requirement to `chainlit-community`.

### Python 3.10 and early 3.11 are no longer supported

- **What changed:** `requires-python` went from `>=3.10,<3.14.0` to `>=3.11.5,<3.14.0`.
- **Who is affected:** deployments on Python 3.10, or on Python 3.11.0 to 3.11.4. Check base images and CI matrices as well as your own machine.
- **What to do:** move to Python 3.11.5 or later, 3.12 or 3.13 before upgrading. On an older interpreter, 3.0.0 does not install.

### Minimum dependency versions are raised

- **What changed:** the lowest accepted versions of these dependencies went up. Upper bounds are unchanged.

  | Dependency         | 2.12.0      | 3.0.0       |
  | ------------------ | ----------- | ----------- |
  | `fastapi`          | `>=0.116.1` | `>=0.133.0` |
  | `starlette`        | `>=0.47.2`  | `>=1.3.1`   |
  | `python-socketio`  | `>=5.11.0`  | `>=5.16.2`  |
  | `mcp`              | `>=1.28.1`  | `>=1.30.0`  |
  | `python-dotenv`    | `>=1.0.0`   | `>=1.2.2`   |
  | `python-multipart` | `>=0.0.30`  | `>=0.0.31`  |
  | `pyjwt`            | `>=2.13.0`  | `>=2.15.0`  |

- **Who is affected:** projects that pin or cap one of these below the new minimum, in their own requirements or through another dependency. The largest step is `starlette`, which moves from the 0.x series to 1.x. Apps that use FastAPI or Starlette directly next to Chainlit (custom routes, middleware, working with `app.routes`) run on those newer versions too.
- **What to do:** remove or raise the conflicting pins and let your installer resolve again. If you call FastAPI or Starlette APIs yourself, read their release notes for the versions you skip. One change we ran into: from `fastapi` 0.141, `app.include_router()` no longer flattens the router's routes into `app.routes`, so code that searches `app.routes` for a route by its `path` may no longer find it.

### The LiteralAI data layer is removed

- **What changed:** the module `chainlit.data.literalai` and its `LiteralDataLayer` are gone, and the environment variables `LITERAL_API_KEY`, `LITERAL_API_URL` and `LITERAL_SERVER` no longer configure anything. The LiteralAI service shut down on 2025-10-31.
- **Who is affected:** apps that set `LITERAL_API_KEY` to get persistence (threads, steps, feedback), and code that imports from `chainlit.data.literalai`.
- **What to do:**
  - If only `LITERAL_API_KEY` is set, the app starts **without persistence** and logs a warning saying so. Remove the `LITERAL_*` variables.
  - To keep persistence, either set `DATABASE_URL` to use the built-in data layer, or register your own with `@cl.data_layer`. The built-in data layer imports `asyncpg`, which is in the `custom-data` extra: install `chainlit-community[custom-data]`.
  - Remove imports of `chainlit.data.literalai`; they raise `ModuleNotFoundError`.
  - A data layer registered with `@cl.data_layer` takes precedence over `DATABASE_URL`, which takes precedence over the `LITERAL_API_KEY` warning.

### The `literalai` package is no longer a dependency

- **What changed:** the generation and step types (`cl.ChatGeneration`, `cl.CompletionGeneration`, `cl.GenerationMessage`, ...) and the instrumentation behind `cl.instrument_openai()` and `cl.instrument_mistralai()` now live in Chainlit. `literalai` is no longer installed with Chainlit, and neither are the packages that only it required: `traceloop-sdk`, `chevron`, the `opentelemetry-instrumentation-*` and OTLP exporter packages, `anthropic`, `grpcio`, `cuid`, `inflection` and `docstring-parser`.
- **Who is affected:**
  - Apps that `import literalai`, or one of the packages above, without listing it in their own dependencies.
  - Code that runs `isinstance()` checks between `literalai` generation objects and `cl.ChatGeneration` / `cl.CompletionGeneration`. These are now Chainlit's own classes, so the checks no longer match. The fields and the serialised form are unchanged.
- **What to do:**
  - Add every package you import yourself to your own dependencies.
  - Create generations from the `chainlit` classes rather than the `literalai` ones.
  - Stop passing `literalai_*` keyword arguments (`literalai_tags`, `literalai_metadata`, ...) to instrumented OpenAI and Mistral AI calls. They are still accepted for now, and may be removed in a future release.

### Session ids are validated

- **What changed:** the `sessionId` in the Socket.IO auth payload must match `[A-Za-z0-9_-]{1,128}`. A connection with a missing or non-matching id is refused with `invalid session id`.
- **Who is affected:** custom clients that connect to the Chainlit Socket.IO endpoint with their own session ids containing other characters (such as `.`, `:` or `/`) or longer than 128 characters. `@chainlit/react-client`, which the bundled frontend and the copilot use, generates UUIDs and is not affected.
- **What to do:** generate session ids that match the pattern, for example a UUID.

## Other notable changes

- `cl.instrument_mistralai()` raises `ModuleNotFoundError` instead of a generic `Exception` when `mistralai` is not installed. `except Exception` still catches it.
- `cl.instrument_mistralai()` no longer breaks streaming calls (`chat.stream`, `fim.stream` and their `_async` variants) on mistralai 1.x releases that return `EventStream` objects.
- `cl.instrument_openai()` no longer fails on responses without `usage`.
- When `CHAINLIT_ROOT_PATH` is set, the auth cookie is now set and cleared with that path. Before, the path was always `/`. `CHAINLIT_AUTH_COOKIE_PATH` now also applies when the cookie is set, not only when it is cleared.
- The debug button's tooltip no longer names Literal AI. Its label is the new translation key `chat.messages.actions.debug`.
- `chainlit lint-translations` now exits with status 1 when a translation file differs from the packaged `en-US.json`. Before, it printed the differences and exited 0, so a CI step that runs it starts failing on translation files that were already out of date.
- Resuming a thread is more robust. With the built-in data layer, an element stored without a `url`, `mime` or `objectKey` no longer comes back with the string `"None"` in that field. A storage provider that fails to produce a read URL for one element no longer aborts the whole resume; a warning is logged instead. `Element.from_dict` keeps `bytes` content as bytes instead of turning it into its string representation. If the resume still fails, the user gets the error "Failed to load conversation history."
- The per-session chat context is now removed together with the session after a disconnect; it used to stay in memory for the lifetime of the server. A failing `@cl.on_chat_end` callback no longer skips the rest of the disconnect cleanup.
- Building from source needs Node 24 or later. Installing a wheel does not need Node at all.
- `@chainlit/react-client` is version `0.6.0`. This fork does not publish it to npm yet; the tarball is attached to each [GitHub release](https://github.com/chainlit-community/chainlit/releases). Its one source change since 2.12.0 is in `useChatSession`: when a thread is resumed, elements that have a `chainlitKey` but no `url` get their URL resolved, as elements received during a session already did, and `null` entries in the thread's elements are ignored.
- Besides official versions, every commit on `main` that passes CI is available as a preview build on GitHub Releases. See [Installation](../../README.md#installation).

The full list is in the [changelog](../../CHANGELOG.md).

## Verify the install

```sh
pip show chainlit-community   # Version: 3.0.0
pip show chainlit             # WARNING: Package(s) not found: chainlit
chainlit --version            # Chainlit, version 3.0.0
python -c "import chainlit; print(chainlit.__version__)"   # 3.0.0
chainlit hello
```

`chainlit hello` should open the hello app in your browser. Then start your own app and check the log for the LiteralAI warning described [above](#the-literalai-data-layer-is-removed).

To check the downloaded files against their checksums and build provenance, follow the instructions at the end of the release notes.
